## T06 · 플랜두씨 JLPT 공부 다이어리

## 현재 구현 범위 (2026-09-30)

과제 6 카드 1~5의 계획·할 일·공부 기록·돌아보기·전체 자료 내보내기를 구현했다.
계획 이름, 기간, 우선순위, 성공 기준, 기간 내 총 예상 시간(분)을 입력한다.
서버 D1 데이터베이스에 저장하며, 수정 시 같은 계획 ID 아래 새 버전을 추가한다.
처음 세운 계획과 이전 버전은 덮어쓰지 않는다. 동시 수정은 버전 충돌로 거절한다.

사용자 공부 설정: JLPT N2, 2026년 12월 목표, 1년 전 N3 합격, 요일 자유 주 4회·30분.
첫 계획 초안만 화면에 제안하며, 날짜를 정하고 저장하기 전에는 DB에 생성하지 않는다.
학습 횟수나 실제 실행 기록은 자동 생성하지 않는다.

카드 2의 할 일 추가·수정·완료·완료 취소·삭제를 구현했다. 각 할 일에는
마감일·우선순위·태그·예상 시간이 있다. 목록에서 제목과 태그 검색,
완료 상태와 우선순위 필터, 마감일·우선순위·생성일·이름순 정렬을 제공한다.
할 일은 서버 D1에 저장하며 삭제된 항목은 목록에서 제외하고 DB에는 삭제 시각을 남긴다.
동일한 완료 요청을 여러 번 보내도 버전과 완료 시각은 한 번만 바뀐다.

카드 3의 실제 공부 기록을 구현했다. 할 일을 골라 시작·종료 시각, 실제 공부 시간,
공부한 내용과 막힌 이유를 입력하며 수정·삭제할 수 있다. 기록은 별도 D1 테이블에
저장된다. 같은 기록 ID의 중복 저장은 거절하고, 수정·삭제에는 버전 검사를 사용한다.
기록을 저장해도 할 일은 자동 완료되지 않으며, 기존 완료 버튼은 반복 요청해도
완료 시각과 버전이 한 번만 바뀐다. 2026-09-30 사용자 제공 실제 공부 기록 3건(총 90분)을
등록했다. 테스트 기록 2건은 사용자 요청으로 삭제 표시해 화면·집계에서 제외했다.
첫 계획 시작일은 9/27로 수정했고, 할 일 5개 중 3개를 실제 학습 내용으로 수정해 완료 표시했다.

카드 4의 돌아보기 화면은 선택한 계획의 할 일과 실제 공부 기록으로 계획·완료·지연·막힘
개수와 예상·실제·차이(실제−예상)를 계산한다. 숫자를 누르면 해당 근거 할 일 또는 기록을
보여 준다. 개선점 한 가지를 뒤따르는 계획에 연결해 저장하면 그 계획의 돌아보기에서도
볼 수 있다. 개선점은 사용자가 직접 입력하며 수정 번호가 맞을 때만 덮어쓴다.
`[테스트]` 표시가 있는 실행 기록도 집계에 포함된다는 안내를 화면에 보여 준다.

## 아직 남은 과제 범위

- 실제 자료를 배포 DB에 옮기는 절차 준비 (로컬 자료는 자동 복사되지 않음)
- 최종 기능·보안 및 제출 검증
- 공개 결과물 URL과 공개 소스 full-commit URL 준비

Sites에 등록된 같은 사이트로 첫 공개 배포를 준비한다. 2026-09-30 사용자가 기존 외부 소스
저장소 업로드와 실제 공부 자료 공개를 승인했다. 로컬 기능 검증은 FINAL_QA.md에 있다.
로그인 없이 읽고 수정하는 공동 자료 구조이며, 공개된 자료만 입력한다.
삭제된 테스트 기록은 로컬에 보존하고 배포할 활성 자료에서는 제외한다.

- 스키마: db/schema.ts
- 스키마 계약: contracts/pds-schema-v2.json (현재 단계 기준, 이후 확장)
- 마이그레이션: drizzle/0000_colorful_toad.sql
- 서버 DB 접근: db/plans.ts
- API: GET /api/plans, GET /api/plans?id=<UUID>, POST /api/plans
- 할 일 DB 접근: db/tasks.ts, 마이그레이션: drizzle/0001_groovy_norrin_radd.sql
- 할 일 API: GET /api/tasks?planId=<UUID>, POST/PATCH/DELETE /api/tasks
- 공부 기록 DB 접근: db/study-logs.ts, 마이그레이션: drizzle/0002_wild_dust.sql
- 공부 기록 API: GET /api/study-logs?planId=<UUID>, POST/PATCH/DELETE /api/study-logs
- 돌아보기 DB 접근: db/reviews.ts, 마이그레이션: drizzle/0003_fluffy_hardball.sql
- 돌아보기 API: GET /api/reviews?planId=<UUID>, POST /api/reviews
- 전체 자료 API: GET /api/export — 원본 열 이름과 값, 수정 이력 및 삭제한 행까지 JSON 파일 하나에 저장
- 개발 서버: node scripts/run-framework.mjs dev --hostname 127.0.0.1 --port 5176
- 타입 확인: node node_modules/typescript/bin/tsc --noEmit
- 로컬 통합 검사: PDS_TEST_ORIGIN 환경 변수에 로컬 URL을 지정하고 node scripts/check-plan-api.mjs
- 내보내기 검사: node --experimental-vm-modules scripts/check-export-api.mjs (메모리 DB만 사용; 실제 자료를 변경하지 않음)
- 로컬 D1 내보내기 대조: 위 검사에 PDS_TEST_ORIGIN과 PDS_TEST_DB_FILE을 함께 지정. 자세한 방법은 CARD5_QA.md.

## 전체 자료 내보내기

화면 맨 아래 카드 5의 ‘JSON 파일 다운로드’를 누른다. 저장한 모든 계획·수정 이력·할 일·공부 기록·돌아보기를 포함한다.
삭제한 할 일·공부 기록과 테스트 기록도 보존하며, 저장하지 않은 입력은 포함하지 않는다.
DB를 수정하지 않고 다섯 표를 하나의 읽기 전용 D1 배치로 조회한다. 비어 있는 표는 빈 배열로 저장한다.
파일에는 스키마 계약·내보낸 UTC 시각·서울 시간대·분 단위 안내가 함께 있다.
표·열 이름은 DB와 같고, tags는 JSON 문자열이며 ID·날짜·버전·null·삭제 시각을 유지한다.
서버 오류 시 다운로드를 만들지 않고 재시도 안내를 보여 준다. 파일을 앱으로 다시 가져오는 기능은 없다.

설치와 빌드에는 Sites 스킬의 helper를 사용한다. 이 PC에 기본 npm 실행 파일이 없어
.sites-runtime/bin/npm.cmd에서 checkout 안의 npm 도구를 실행하도록 준비했다.
.sites-runtime, .wrangler, node_modules, dist는 소스 저장소에 포함하지 않는다.
로컬 D1 데이터는 배포 데이터로 복사되지 않는다.
