# T07 진행 계획

확인일: 2026-09-30 (Asia/Seoul).
안내: https://aleph-omega.vercel.app/cortex?panel=tasks 의 T07 본문과 카드 1~5.

## 출발점

T06 최종 제출 커밋 `cade4b42bbbcbaf44f876b3c80fc6564833b790f`에서 새 T07 저장소를 시작한다.
원본 커밋을 T07 이력의 조상으로 유지한다(C78). 결과물과 소스의 출처는 T06_PROVENANCE.json에 있다(C77).
T07에는 별도의 Sites 프로젝트와 DB를 생성한다. T06 프로젝트 ID는 T07 hosting 설정에서 제거했다.
기존 T06 운영 자료는 저장소 밖 `../backups/`에 보관한다. 공개 저장소에는 자료 백업과 계정 비밀값을 넣지 않는다.

## 현재 단계

소스 이력 보존과 자료 백업을 준비하는 단계다. 인증, 계정별 권한 검사, 자료 이전, 새 배포는 아직 구현하지 않았다.
실제 5일 사용 실험은 인증과 자료 차단을 검증한 T07 앱에서 시작한다. 이전 T06 기록은 자료 이전 대상이며 T07 실험 5일의 기록으로 간주하지 않는다.

## 구현 순서

1. Better Auth + Drizzle/D1 호환성을 작은 가입·로그인 흐름으로 검증하고 사용 버전을 고정한다.
   선택 후보는 라이브러리 방식이다. 직접 구현과 외부 인증 서비스를 비교해 선택 이유 및 기각 이유를 남긴다.
   공식 참고: https://better-auth.com/docs/adapters/drizzle 및 https://better-auth.com/docs/installation.
   최종 방식·버전·비밀번호 처리 방법은 런타임 검증 뒤 확정한다.
2. 가입·로그인·로그아웃·비밀번호 변경·세션 만료를 구현한다. 중복 가입을 막고, 없는 계정과 틀린 비밀번호의 로그인 안내 문구를 같게 한다.
   서버에 보관하는 세션과 쿠키로 인증한다. 로그아웃 및 비밀번호 변경 뒤 이전 세션이 실제로 거절되는지 검증한다.
3. 서버에서 확인한 계정 ID를 모든 자료 조회·생성·수정·삭제·이력·돌아보기·내보내기에 적용한다.
   클라이언트가 URL·헤더·본문에 보낸 계정 ID를 권한 근거로 사용하지 않는다.
   다른 계정의 계획·할 일·공부 기록·개선점 연결도 서버에서 거절한다. 거절 전에 저장하지 않는다.
4. 본인 계정 생성 후 백업 자료를 원본 ID·이력·실제 공부 시각을 유지하며 이전한다.
   첫 방문자 또는 첫 가입자에게 원본 자료를 자동 배정하지 않는다. 원본 자료를 코드에 포함하지 않는다.
5. 테스트 계정 두 개로 양방향 읽기·수정·삭제 및 목록·내보내기 분리를 검증한다.
   실패 응답은 403 또는 존재를 감추는 404이며, 미인증 요청은 거절한다.
   테스트는 본인 실제 자료와 분리하고 제출 증거에는 계정 비밀번호·세션·토큰·키 원문을 가린다.
6. 내 자료 전체 JSON 내보내기 및 계정 삭제/자료 삭제 안내를 구현한다.
7. T07을 별도 프로젝트로 배포하고 익명 접속 시 공개 로그인 화면만 표시되는지 검증한다.
8. 잠긴 앱에서 실제 날짜 5일 사용을 시작한다. 사용자 실제 입력만 기록하고 날짜를 소급하거나 자동으로 실행 기록을 만들지 않는다.

## 실제 5일 실험에서 고정할 것

첫날 질문 한 문장, 지표 한 개, 단위, 계산 규칙, 첫 계획 규칙을 정한다.
결측·중복·이상값·반올림 처리와 주 시작 요일을 함께 적는다.
Asia/Seoul 기준 서로 다른 실제 날짜 정확히 5일을 본인 계정 안에 기록한다. 연속 날짜라는 조건은 없다.
2일차 기록 후 3일차 기록 전에 계획 규칙 하나만 바꾸고, 실제 변경 시각·이유 및 근거가 된 1·2일차 기록 ID를 남긴다.
규칙 변경 전후에 같은 지표·단위·계산 규칙을 적용하고 화면 합계·평균을 손계산과 대조한다.
질문과 규칙은 아직 사용자가 결정하지 않았으며 예시를 확정된 사용자 판단으로 기록하지 않는다.

## 제출물

- 첫 화면이 로그인 화면인 공개 결과물 URL. 심사자가 계정을 만들지 않아도 첫 화면은 열려야 한다(C01/C03).
- T06 고정 커밋이 조상인 공개 소스의 전체 commit URL(C78).
- 인증 구현 설명서: ① 무엇으로 붙였나 ② 왜 골랐나 ③ 어디를 어떻게 고쳤나 ④ 차단 확인 기록 ⑤ AI와 나 ⑥ 아직 못 막은 것과 위험.
- ③에 가입·로그인·로그아웃·자료 조회의 소스 흐름을 적고 ④에 성공/거절 요청을 나란히 적는다.
- 확인 방법 4줄: 어디로 / 세 단계 안의 행동 / 통과 화면 / 실패 화면.
- AI와 내 판단 3줄: AI에 맡긴 일 / 본인 판단 / 따르지 않은 제안 또는 없었던 이유.
- 실제 5일의 기록·규칙 변경·계산 대조·내보낸 자료 파일. 비밀번호·세션·토큰·비밀키 원문은 공개 화면·소스·증거에서 가린다.

아직 검증하지 않은 내용을 통과로 표시하지 않는다. 인증 구현 설명서의 여섯 번째 항목은 실제 미구현 사항과 위험을 작성한다.
