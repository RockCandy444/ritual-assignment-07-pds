# T07 인증 구현 설명서

인증 검증 시각: 2026-09-30 15:56:02 Asia/Seoul. 실험·JSON 확인일: 2026-10-06. 서로 다른 실제 날짜 5일의 기록과 계산 확인을 마쳤으며, 사후 규칙 문서화 한계를 아래와 실험 결과 문서에 구분해 남겼다. 사용자가 제출용 공개 접근과 문서 반영을 승인했다. 2026-10-06 Sites 접근 모드를 public으로 변경했다. 이 설명서와 실험 자료를 최종 소스에 반영한다.

## ① 무엇으로 붙였나

라이브러리 방식: **Better Auth 1.7.6**, **@better-auth/drizzle-adapter 1.7.6**.
기존 React/Vinext + Cloudflare Workers/D1 앱에 이메일·비밀번호 인증을 붙였다.
세션은 서버 D1의 `auth_session`에 저장하고 브라우저에는 HttpOnly 세션 쿠키를 발급한다.
HTTPS 운영 환경에서는 Secure 쿠키, SameSite=Lax를 사용한다. 응답 JSON에서 세션 토큰을 제거한다.
소스의 비밀값은 설정 이름뿐이며 운영 비밀키는 호스팅 환경에 따로 보관한다.

T06 최종 제출 커밋 `cade4b42bbbcbaf44f876b3c80fc6564833b790f`를 조상으로 보존했다.
별도 T07 저장소·사이트·DB를 사용한다. [T06 출처](T06_PROVENANCE.json).

## ② 왜 골랐나

기존 SQLite/D1과 Drizzle를 유지하면서 비밀번호 처리·쿠키 발급·서버 세션을 라이브러리로 제공할 수 있기 때문이다.
작은 가입 요청으로 어댑터 호환성을 확인한 뒤 전체 권한 검증을 수행했다.

| 선택지 | 판단 |
| --- | --- |
| 라이브러리 | 선택. 기존 DB와 통합하고 세션·비밀번호 처리를 직접 다시 작성하는 범위를 줄인다. |
| 직접 구현 | 기각. 암호화 함수, 쿠키 서명, 세션 갱신을 모두 직접 유지하기에는 실수할 부분이 많다. |
| 외부 인증 서비스 | 기각. 과제의 비밀번호 저장값과 서버 세션 증거를 기존 DB에서 직접 확인하기 어렵고 별도 서비스 구성이 필요하다. |

비밀번호는 라이브러리 기본 **scrypt**를 사용한다. `N=16384, r=16, p=1, dkLen=64`, 개별 무작위 salt 16바이트.
저장 형태는 `salt(32자리 hex):hash(128자리 hex)`다. 로그인 시 비밀번호를 복호화하지 않고 같은 조건의 계산값을 검증한다.
암호화/해싱 알고리즘을 직접 구현하지 않았다. 테스트 계정 A/B의 같은 비밀번호가 서로 다른 저장값인 것을 DB에서 확인했다.
저장값 샘플은 [가린 검증 증거](auth-evidence.json)의 “같은 비밀번호의 저장값 대조”에 있다. 원문 비밀번호는 포함하지 않는다.

## ④ 차단 확인 기록

실제 로컬 앱 `http://127.0.0.1:5177`와 로컬 D1에서 임시 계정으로 **83건 통과**.
검증기: `scripts/check-auth-live.mjs`. 요청/응답과 시각은 [auth-evidence.json](auth-evidence.json).
임시 계정은 검증 종료 시 삭제했다. 운영 환경 검증이나 실제 공부 기록 5일의 증거는 아니다.

| 성공 요청 | 대조 거절 요청/결과 |
| --- | --- |
| 로그인 전 `GET /diary` 대신 가입/로그인 200 | 익명 `GET /diary` 307 `/`, 자료 API와 내보내기 401 |
| 본인 쿠키로 `GET /api/plans` 200 | 로그아웃 후 **같은 주소·방식·이전 쿠키** 401 |
| A/B 각자의 계획 생성·목록 201/200 | A→B와 B→A의 계획 이력, 할 일/기록/돌아보기 조회·수정·삭제·생성 연결 404 |
| 본인 자료 내보내기 200 | 남의 ID 접근 전후 두 계정의 다섯 표 내용과 건수가 모두 동일 |
| A 본인 목록 200 | URL/헤더의 남의 사용자 값은 무시. 본문의 남의 userId/ownerId로 생성해도 A 소유로 저장 |
| 새 비밀번호 로그인 200 | 변경 전 두 세션 401, 이전 비밀번호 401 |
| 유효한 24시간 세션 200 | DB 만료 시각을 과거로 바꾼 세션 401 |
| 정상 계정 삭제 200 | 틀린 비밀번호 삭제 401. 삭제 후 본인 자료/계정 0행, 이전 쿠키와 로그인 401 |
| 빈 계정에서 T06 가져오기 201 | 다시 가져오기 409, 다른 계정과 ID 충돌 409 및 0행 롤백 |
| 원본 T06 가져온 뒤 내보내기 200 | 원본 다섯 표 모든 열·값·ID·버전·시각을 대조해 일치 |

없는 이메일과 틀린 비밀번호는 같은 401 본문이다. 중복 이메일 가입은 거절됐다.
인증 요청 제한 429에서는 서버가 안내한 대기 시간을 지킨 뒤 다시 검증했다.
공개 증거의 비밀번호·쿠키·토큰 필드를 가리고 실제 비밀값이 남지 않았음을 검증기에서 검사했다.
원본 T06 백업 본문과 가져온 본인 자료는 공개 증거에서 생략했다.

## ⑤ AI와 나

- AI에 맡긴 일: T06 보존·백업, 새 저장소 준비, 인증과 소유자 검사 구현, 임시 계정 검증, 설명서 초안.
- 본인 판단: T06을 기반으로 별도 T07 저장소에서 시작하는 방향을 사용자가 확인했다. 사용자는 하루 실제 공부 시간(분)이라는 지표, 30분 목표, 복습 10분→새 단어 20분 순서, 실제 적용일 10월 4일을 확인했고 실제 공부·기록·완료 처리·돌아보기·JSON 내보내기를 수행했다.
- 따르지 않은 제안: 이 대화에서 사용자가 기각했다고 확인한 AI 제안은 없다. 질문·지표와 공부 순서 제안은 사용자가 확인하고 적용했다. 대화 밖에서 따르지 않은 제안이나 이유는 확인되지 않았으므로 대신 만들어 적지 않는다.

## ⑥ 아직 못 막은 것과 위험

- 이메일 소유 확인, 비밀번호 찾기/재설정, MFA는 미구현이다. 이메일 검증이 없어 다른 사람의 이메일을 먼저 등록할 수 있다. 중복 가입 보호는 이메일 소유 확인을 대신하지 않는다.
- 기본 인증 요청 제한은 Worker 메모리 단위다. 여러 인스턴스에 걸친 공유 제한이나 계정 단위 잠금은 구현하지 않았다. 대규모/분산 로그인 시도에 대한 보호는 충분하지 않다.
- 24시간 세션은 활동 중 1시간 간격으로 갱신될 수 있다. 총 로그인 기간의 절대 상한을 별도로 두지 않았다.
- 자료 내보내기에 계정 비밀번호·세션은 포함하지 않는다. 계정 삭제 전에 내려받은 JSON 복사본과 호스팅 제공자의 내부 보존 자료까지 앱이 지우지는 못한다.
- T06 원본 앱은 기존 공개 범위를 유지한다. T07에서 인증을 붙여도 T06에 남아 있는 원본 자료가 자동으로 비공개로 바뀌지는 않는다.
- 로컬 검증과 빌드가 통과했으며 운영 인스턴스에 대한 전체 공격/부하 검증은 별도로 필요하다. 비밀번호 평문은 앱 로그에 기록하지 않지만 브라우저 개발자 도구에서 본인이 보낸 요청은 확인할 수 있다.
- T07 계정의 실제 날짜 5일 기록, 완료 처리, 돌아보기, 내보내기와 합계·평균 대조를 확인했다. T06 지난 기록과 테스트 기록은 제외했다. 규칙 적용 시작일은 사용자 진술 기준 10월 4일이지만 계획 이력 저장은 10월 6일의 사후 문서화다. 정확한 실제 변경 시각과 공부 전 저장 이력은 입증되지 않아 해당 요구 충족을 통과로 표시하지 않는다. [실험 결과](T07_EXPERIMENT_RESULT.md), [JSON 발췌](T07_EXPERIMENT_EVIDENCE.json).

## 제출 전 상태

1. 가입 및 T06 자료 이전 완료. 비밀번호와 세션을 설명서나 공개 증거에 포함하지 않는다.
2. 질문·지표·단위·계산 규칙과 결측/중복/이상값/반올림/주 시작 요일을 확정했다.
3. 실제 Seoul 날짜 10/1·10/2·10/4·10/5·10/6의 다섯 기록을 확인했다. 1·2일차 근거 기록 ID는 실험 결과 문서에 남겼다. 규칙 변경의 사후 문서화와 실제 변경 시각 미확인 한계도 그대로 남겼다.
4. 합계 148분, 평균 29.6분을 손계산으로 대조했고 본인이 JSON을 내보내 첨부했다. 원본은 로컬 백업으로 보관했다.

6. 실제 5일 증거와 본인 판단을 보완한 뒤 공개 소스의 최종 고정 커밋 URL을 제출한다.

### 확인 방법 4줄

어디로: T07 사이트 첫 화면과 고정 커밋의 이 설명서/요청 증거.
